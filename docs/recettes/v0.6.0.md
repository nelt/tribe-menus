Parcours ciblés demandés par l'analyse :

- `web/recette/recalcul.spec.ts` (entrées 3, 4, 6 à 8), dans les quatre projets : un plat de 4 parts avec « 200 g » d'un ingrédient suffixé de l'exécution, servi demain soir ; ses courses ajoutées à « Courses » (200 g), l'article coché ; dans un second contexte sur la même session, le repas passe à 8 parts ; le premier contexte revient sur l'application : bandeau de liste périmée, pastille « Repas modifiés » dans le choix des listes ; « Recalculer » : « Liste recalculée. », l'article décoché à 400 g, « encore 200 g » ; puis coché et retiré par « Courses faites ».
- `web/recette/selection.spec.ts` (entrées 5 et 11), dans les quatre projets : deux articles ajoutés à la main dans « Courses » ; « Sélectionner », les deux choisis, « Nouvelle liste » nommée d'après l'exécution : bandeau vert, la liste ouverte par son lien les contient ; l'un renvoyé vers « Courses » par « Déplacer vers… », puis l'autre ; la liste vide supprimée depuis le choix des listes (C12, la tribu ne garde pas les listes des exécutions, limitées à 20) ; les deux articles cochés et retirés par « Courses faites ».

Écartés, pistes du plan : la taille de `GET shopping-lists` (aucun seuil ne dit ce qui serait trop ; à mesurer quand un défaut de lenteur se montrera) ; la tablette en portrait (le format moyen n'a rien de propre dans cette version qui ne soit dans les deux autres ; `make e2e-formats` le couvre sur la PR de release).
